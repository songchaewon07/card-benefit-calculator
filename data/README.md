# 시드 데이터 안내

`cards.seed.json`의 카드들은 **실제 카드사 상품이 아닌 가상의 카드**입니다. 혜택 계산 엔진과 UI를 개발/테스트하기 위해 전월실적 조건, 카테고리별 한도, 통합 한도 등 실제 카드에서 흔히 볼 수 있는 구조를 반영해 임의로 작성했습니다.

- 카드사명/카드명은 모두 가상의 이름입니다.
- `source.origin`이 모두 `"manual"`로 표시되어 있으며, 실제 검증된 데이터가 아닙니다.
- 국내 실제 카드사 공식 API/공공데이터 조사 및 크롤링을 통한 검증된 데이터 구축은 **DEV_PROMPTS.md의 Step 2**에서 진행합니다. 이 파일은 그 결과물로 대체될 예정입니다.

`subscriptions.seed.json`의 구독료도 참고용 대략적인 값이며, 정확한 최신 가격은 각 서비스에서 별도로 확인이 필요합니다.

## Step 2 진행 상황 (2026-08-19)

1. **공식 API/공공데이터 조사 결과**: 금융감독원(finlife.fss.or.kr), 여신금융협회(gongsi.crefia.or.kr, openapi.crefia.or.kr), 공공데이터포털(data.go.kr)을 조사했으나, "국내 주요 카드사 전체"의 카테고리별 할인율/적립률/전월실적 조건/한도를 다루는 공식 API·공개 데이터셋은 **없었습니다**. 발견한 것은 개별 은행계 카드(산업은행, 우체국)의 상품 개요 API, 여신금융협회의 수수료율/재무 공시, 가맹점 매출 API 정도로, 우리가 필요로 하는 혜택 상세 데이터는 다루지 않습니다. → 크롤링이 보조가 아니라 사실상 주 수단이 되어야 함을 확인했습니다.
2. **카드사 사이트 크롤링 가능 여부**: `../scripts/crawl-cards/targets.ts`에 카드사별 robots.txt 조사 결과를 기록해뒀습니다.
   - 허용(allowed): 신한카드, KB국민카드 — 범용 User-Agent에 카드/혜택 경로가 명시적으로 열려있음 (dry-run으로 실제 200 응답 확인)
   - 불확실(uncertain): 현대카드, 하나카드, 우리카드 — 지정된 검색엔진/AI봇에만 선택적으로 허용, 범용 크롤러 기준 판단 불가
   - 차단(blocked): 삼성카드(robots.txt에서 범용 봇 전체 차단), 롯데카드(자동화 요청 시 연결 차단 추정 — 우회 시도 안 함)
3. **크롤러 골격**: `../scripts/crawl-cards.ts` (`npm run crawl:cards`)에 robots.txt 실시간 재확인, 요청 빈도 제한, 정직한 User-Agent 식별을 갖춘 골격을 구현했습니다.
4. **표 추출기 구현 및 실제 페이지 검증** (`../scripts/crawl-cards/extract.ts`): 신한카드·KB국민카드 실제 카드 상세페이지를 직접 열어 구조를 확인한 뒤, `<table>`을 caption/헤더/행 단위로 구조화해 추출하고 `<caption>연회비</caption>` 표에서 연회비를 파싱하는 로직을 구현·검증했습니다.
   - 실행 결과 예시: KB "Easy all 티타늄카드" 페이지에서 표 11개(연회비, 전월실적 구간별 한도, A~D 그룹별 할인 카테고리 등)를 정확히 추출, 연회비 30,000원까지 정확히 파싱됨. 신한 체크카드 페이지에서는 통합 적립한도 표(전월실적 구간 3단계)를 정확히 추출, 연회비 표는 없음(체크카드라 실제로 연회비가 없는 것으로 추정)을 올바르게 인식.
   - 실행: `npm run crawl:cards [issuerId]` → `scripts/crawl-cards/output/<issuerId>.json`에 저장 (참고용 초안, git에는 커밋하지 않음).
   - **의도적으로 하지 않은 것**: 카테고리별 할인율/적립률을 `Card`/`BenefitRule` 타입으로 완전 자동 변환하는 것. 실제로 확인해보니 카테고리 매핑은 카드마다 자유 문장이거나(신한: "Dream 영역 최대 1% 적립" 같은 prose), 카드사 고유의 복잡한 메커니즘(KB: "전월실적 구간별로 많이 쓴 상위 N개 영역에 자동 캐시백" 같은 동적 로직)으로 되어 있어, 우리 데이터 모델(카테고리 고정 + 고정 한도)에 억지로 끼워 맞추면 조용히 틀린 숫자를 만들어낼 위험이 큽니다. 대신 추출기는 사람이 검토하기 쉬운 구조화된 표(caption + 행) 형태로 정리해주는 데까지만 하고, `data/cards.seed.json`으로의 최종 반영(카테고리 매핑, 단순화 판단)은 사람이 합니다.
   - 남은 이슈어(현대/하나/우리/삼성/롯데)는 여전히 `uncertain`/`blocked` 상태이며 그대로 둡니다.
